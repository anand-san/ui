# Used in Eloovor

[Eloovor](https://www.eloovor.com) is a job search workspace, and the app san-ui was extracted from. This page shows how one app puts san-ui together: a theme, a few domain colors, and thin app components on top of the generic ones. Use it as a worked example for your own app.

## The theme: ink and highlighter

The look comes from the logo and from what job seekers do on paper: mark up a job ad with a pen and a highlighter. `themes/eloovor.css` fills in the base:

- **Ink** is the logo violet `#574a7d` (`brand-600`). The neutrals lean toward it (`--tint-hue: 252`), so greys read as thinned ink.
- **Highlighter** is marigold (the `highlight-*` ramp): matched keywords in a job ad, "New" badges, the assistant's suggestions.
- **Type** is Bricolage Grotesque for display, title and heading, and Figtree for the rest, both self-hosted from `@fontsource-variable`.

```css
/* src/index.css */
@import '@fontsource-variable/figtree';
@import '@fontsource-variable/bricolage-grotesque/opsz.css';
@import '@sandilya/ui/tokens.css';
@import '@sandilya/ui/themes/eloovor.css';
@import '@sandilya/ui/base.css';
@import './components/status/status.css';
```

## Domain colors: the pipeline statuses

An opportunity moves through seven statuses, more than the seven Badge tones can tell apart, so Eloovor defines one color per status in its own CSS, light and dark:

```css
/* src/components/status/status.css */
:root,
.force-light-mode,
.dark .force-light-mode {
  --status-to-apply: 300 48% 43%; /* orchid */
  --status-applied: 214 72% 44%; /* blue */
  --status-interviewing: 36 92% 31%; /* ochre */
  /* … */
}

.dark {
  --status-to-apply: 300 60% 74%;
  /* … */
}
```

and names them in its own Tailwind config, next to the preset:

```js
// tailwind.config.js
import preset from '@sandilya/ui';

export default {
  presets: [preset],
  content: ['./index.html', './src/**/*.{ts,tsx}'],
  theme: {
    extend: {
      colors: {
        status: {
          'to-apply': 'hsl(var(--status-to-apply))',
          applied: 'hsl(var(--status-applied))',
          /* … */
        },
      },
    },
  },
};
```

The class maps are written out in full so Tailwind generates every class:

```ts
export const statusSoftClass: Record<OpportunityStatus, string> = {
  [OpportunityStatus.TO_APPLY]: 'bg-status-to-apply/10 text-status-to-apply',
  [OpportunityStatus.APPLIED]: 'bg-status-applied/10 text-status-applied',
  // …
};
```

## App components on top of san-ui

App components hold the domain: the type, the data and the mutation. The look and behavior come from san-ui. The status dropdown on every opportunity card is a `StatusMenu` with the pipeline colors:

```tsx
import { StatusMenu, type StatusOption } from '@/design-system';

const statusOptions: StatusOption<OpportunityStatus>[] = statusOrder.map(
  status => ({ value: status, className: statusSoftClass[status] }),
);

export function OpportunityStatusDropdown({ opportunity }: Props) {
  const updateStatus = useUpdateOpportunityStatus();
  return (
    <StatusMenu
      value={opportunity.status}
      options={statusOptions}
      label="Opportunity status"
      onValueChange={newStatus => updateStatus({ opportunity, newStatus })}
    />
  );
}
```

A read-only status is the same component without `onValueChange`. Because `StatusMenu` keeps its clicks to itself, it sits inside the linked opportunity card without opening the card.

## What stays outside san-ui

- **Printed pages**: the resume preview and PDF sit inside `.force-light-mode` and keep fixed neutrals and Helvetica, so the preview matches the download.
- **The Elo assistant**: the glass dock and chat keep their own glass styling.
- **Domain components** like the opportunity card, the Kanban board and the analysis reports are app code built from san-ui parts.

## Migrating the app onto san-ui

Eloovor started as shadcn/ui components copied into `src/components/ui/`. Every screen has since moved onto san-ui. These replacements were specific to Eloovor; the generic ones are in the README's migration table.

- `SOFT_CARD_CLASS`, `bg-neutral-50 dark:bg-neutral-900` cards → `<Card>`
- `CONFIG_ITEM_CLASS`, `bg-primary/5 rounded-xl` children → `<Card variant="tinted">`
- `bg-chat-user` banners → `<Card variant="brand">` with `inverse` buttons
- `statusColors` / `statusTextColors` → `statusFillClass` / `statusTextClass`
- A status `Badge` with `statusColors[status]` → `StatusMenu` with the pipeline colors
- `IllustratedMessage` → `<EmptyState image>`
- `RainbowButton` → `<Button size="lg">`
- `CircularProgress` → `<ScoreRing>`

Design changes that came with the migration, on purpose:

- Child card hover is `bg-primary/10`, which darkens in light mode. It used to be `neutral-100`, which was lighter than the card.
- Status colors are tuned per theme, so status text is readable on both. The app used one 500 step everywhere, which put yellow text below contrast on white.
- Item cards are spaced only by the list gap; `OpportunityCard` also added `mb-2`, doubling it.
- Status badges are soft (a tint behind colored text) instead of solid with white text, which failed contrast for yellow and for every status in dark mode.
- Labels, titles and buttons are sentence case, and the all-caps form headings are gone.
- Profile list sections (experience, education, awards…) are one card each, with the add button in the card header.
- Toasts use the theme tokens instead of sonner's rich colors.
- Required fields show a muted asterisk from `Field`, instead of a hand-typed `*`.
- Resume editor fields are 32px high everywhere (`Field size="sm"`).
